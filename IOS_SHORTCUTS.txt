KANKOO: IPHONE SHORTCUTS FORWARDING
Branch: feature/ios-support. Based on stable Android main, separate from the
CA evidence plan in feature/ca-evidence-ledger. Minimum iOS version: 17.0.

WHAT IS IMPLEMENTED
Apple's native App Intent, "Forward bank message", accepts message text and
an optional sender. It saves new input to an AES-256-GCM encrypted inbox in
the app sandbox. It does not read the Messages inbox or return ledger data.
Forwarding is off until the user enables it in Kankoo's iPhone Shortcuts
settings. No webhook, account or forwarding server is required.

The foreground app imports pending records only after onboarding and any
enabled app lock are satisfied. Acknowledgement deletes a native record only
after the ledger/raw-message commit succeeds. Stable event IDs make a retry
after commit-before-ack safe. Unparsed/ignored messages remain in the ledger's
message history. Parser classification is not a guarantee every bank format
will parse; review Activity and messages for your bank.

Inbox keys use Keychain AfterFirstUnlockThisDeviceOnly. Ciphertext files are
excluded from device backups and use CompleteUntilFirstUserAuthentication
file protection. A lost/unavailable key or damaged file is preserved, never
silently reset. The inbox holds 500 events, 32 KB of UTF-8 text per event and
512 bytes per sender; overflow fails visibly in Shortcuts. Import pending
messages before backing up Kankoo: pending native files are intentionally not
part of its ledger backup and will not transfer to a replacement device.

SETUP ON AN IPHONE WITH A SIGNED KANKOO BUILD
1. Open/unlock Kankoo, finish onboarding, then enable Allow Shortcuts forwarding
   in Settings > iPhone Shortcuts. This creates the encrypted inbox key.
2. Open Apple Shortcuts > Automation > New Automation > Message.
3. Choose a bank sender or a transaction phrase that matches actual messages.
   Select Run Immediately when available. Avoid overlapping automations for
   the same bank message; each new invocation creates a new capture event.
4. Add Kankoo's "Forward bank message" action. Set Bank message to Shortcut
   Input and choose its Content detail. Do not pass the Sender/contact object
   as message text. Sender is optional; choose its Sender detail if available.
5. First test the action in an ordinary shortcut with a Text action containing
   a synthetic bank alert. Example:
   Sent Rs.250.00
   From HDFC Bank A/C *4521
   To TEST MERCHANT
   On <today's date in DD/MM/YY>
   Ref <a unique 12-digit synthetic number>
6. Open/unlock Kankoo and verify Activity's exact amount, direction, account,
   merchant and receipt time. Then test a real Message-trigger automation.
7. Confirm locked-phone delivery, background delivery and a phone restart on
   your device. The inbox is unavailable before the first unlock after reboot.
   A failed action should be retried after unlocking; Apple controls scheduling.

The older kankoo://ingest?text=<URL-encoded text>&sender=<URL-encoded sender>
method remains a fallback. It opens the app and may require unlocking. Encode
each value independently; never interpolate raw message text into a URL.
Native SceneDelegate captures cold and warm links before Flutter routing.
No text or complete URLs are logged by this forwarding implementation.
Optional cloud AI can process imported records only under existing AI settings;
the forwarding action itself does not make a network request.

BUILD AND TEST WITHOUT OWNING A MAC
GitHub Actions .github/workflows/ios.yml uses a macOS runner and Xcode 26.3
(connectivity_plus 7.3.2 references an iOS 26 SDK API). The deployment target
remains iOS 17; compiling with a newer SDK does not require iOS 26 to install.
The workflow runs native inbox tests, Flutter analysis/tests, an unsigned
iPhone release build, a simulator build, native simulator XCTest coverage and
a Flutter integration test of the real bridge, Keychain and SQLCipher ledger.
Its unsigned .app artifact cannot be installed directly on a physical iPhone.
Apple signing/provisioning is still needed for device installs or TestFlight.
No signing credentials are stored in this branch.

PHYSICAL ACCEPTANCE CHECKS STILL REQUIRED BEFORE A PUBLIC IOS RELEASE
- Discover Kankoo's action after install/update in the actual Shortcuts app.
- Verify selected bank sender, Content mapping and Run Immediately behavior.
- Deliver once foreground, background, app terminated and phone locked.
- Reboot: verify failure before first unlock and successful capture afterward.
- Enable Kankoo app lock: capture while locked, no ledger import until unlock.
- Interrupt import; reopen and verify no lost or duplicated ledger record.
- Check OTP/non-transaction handling and unfamiliar bank formats in messages.
- Test oldest supported iOS 17 and a current iOS release on real devices.
Simulator/programmatic AppIntent tests cannot certify SMS-trigger scheduling,
lock-screen execution, App Store review or a specific bank sender's delivery.
