Database and integrity
Schema version 5 adds import_jobs, documents, invoices, invoice_lines,
source_events, classifications, business_rules, payment_allocations,
review_events, export_runs and export_items. Existing transactions gain
business_use_bps and review_status. Existing SourceKind indexes are preserved.
The upgrade runs in one transaction and retains existing IDs, notes, categories,
accounts, raw-message links, currency fields and indexes. No destructive reset.
Runtime foreign-key enforcement is enabled. Monetary fields use INTEGER paise;
CHECK constraints reject fractional amounts and invalid percentages/tax equations.

Source identity is unique per (source, source_account_id, external_id).
Import file hashes are unique per source and account. Jobs record original file
hash, parser version, mapping, declared balances, totals and exact row outcomes.
Source/job account consistency is guarded in both update directions.
Allocation triggers guard each transaction's gross allocated amount, each
invoice's net paid amount, direction, currency, refunds and parent edits.
Partial and combined payments are supported by the schema; their UI is 1B.
Classification, rule and allocation edits produce JSON before/after audit events
with provenance. Review events reject normal UPDATE and DELETE operations.
This is application-level audit protection, not legal immutability against a
device owner. Explicit full-ledger restore replaces history atomically.

CSV import behavior
UTF-8 CSV (optional BOM), comma/semicolon/tab delimiters, quoted fields and
CRLF/LF endings; maximum 10 MB and 50,000 transactions. Header-row selection,
explicit date formats and oldest/newest-first ordering. Separate debit/credit
columns or amount plus a direction marker. Optional running balance, UTR/reference
and bank transaction ID columns. User selects or adds an active INR bank account.
Opening and closing balances must be entered from the bank statement.
All rows, mapped running balances and opening + credits - debits = closing must
pass before a single row is committed. Amounts are never rounded from floats.
Malformed rows, conflicting source IDs or a failed DB write roll back the import.
Exact file repeats are blocked. Overlapping exports with stable IDs are skipped.
Source tombstones survive transaction deletion, preventing silent resurrection.
Strong account/reference/amount/direction/date matches link existing payments and
preserve user edits. Equal amounts alone never trigger an automatic merge.
Possible overlaps are retained for review, not silently dropped.
Without a bank ID, identity is a normalized row hash plus occurrence number.
Changing mappings or exports without stable IDs can create reviewable overlaps;
test actual bank samples before treating bank support as certified.

Encrypted PDF vault
Original bytes are hashed for identity and encrypted with AES-256-GCM, fresh
nonces, per-file HKDF-SHA256 keys derived from the existing device-bound DB key,
and authenticated version/hash context. No new master key is silently created.
Files are ciphertext-only .kpdf files; temporary writes are also ciphertext.
Metadata remains inside SQLCipher. Failed authentication, missing/wrong keys and
DB failures preserve original files and keys. Verified encrypted orphan files can
be recovered on retry. Hash duplicates reuse the existing document.
Hashing/encryption/decryption and CSV preview validation run off the UI thread.
PDF intake checks the header, end marker and 25 MB limit. It does not render,
OCR, extract invoice fields, certify PDF safety or establish tax eligibility.
The service can decrypt into memory; an invoice viewer is not part of 1A.

Backups
Existing database-only backups remain available when there are no vault PDFs.
Schema-5 backups must contain every schema-5 table; earlier backups remain
compatible with defaults. Restore validates foreign keys and allocation/source
invariants before committing and reinstalls audit guards without fabricating edits.
When PDFs exist, database-only backup creation is blocked with an explanatory
message. A metadata-only PDF backup is rejected on restore. A complete portable,
encrypted vault backup has not been implemented; users must keep original PDFs.
The PDF import screen explains this limitation before attachment.

UI
Open Settings > Statements & evidence. Scoped neutral light/dark theme with
FAFAFA/0F1115 backgrounds, thin borders, ink primary actions, tabular date and
money styles, Indian grouping and exactly two decimal places. Emerald indicates
reconciliation; amber requests review; crimson identifies mismatch. No charts,
marketing filler or pretend invoice matches. Live column samples, row-level
errors, mismatch-blocked import, duplicate-blocked import and explicit success
counts. One scrollable phone workflow and wider multi-column mapping layouts.
Large-text reconciliation wraps without horizontal overflow.
